# 抖音接入（可选 · 有风险）

> 🔴 **本包不含任何抖音自动化代码。** 它只做三件事：声明风险、记录你的明确确认、检查本地前置条件。
> 想要自动化的人自己接；接之前请先把下面的声明读完。

## 风险声明

1. 自动操作抖音（点赞 / 评论 / 私信 / 关注 / 刷视频）通常**违反平台用户协议**，可能导致账号被限流、封禁，甚至牵连设备。
2. 页面随时改版，自动化会**静默失效**；失效时可能重复发送或发错对象。
3. 不要用它群发、骚扰、刷量、冒充他人——这些不只是封号问题，可能涉及**法律责任**。
4. 只用自己的**小号**、**低频**操作；不要把主人的账号、凭据、住址等信息写进任何配置。
5. 本包不提供绕过风控、破解签名、批量账号等能力。
6. **后果由使用者自己承担。** 作者不对账号损失、数据丢失或法律后果负责。

## 它提供什么

| 工具 | 作用 |
|---|---|
| `douyin_optional_status` | 是否已确认风险、本地前置条件（浏览器 / 独立 profile / 凭据文件）是否满足；返回里始终带声明 |
| `douyin_optional_acknowledge` | 记录「已阅读并接受风险」的确认（本地 JSON，带时间戳和用途），必须 `confirm: true` |

确认文件：`~/.dsh/shared/companion/douyin-risk-ack.json`

## 怎么用

1. 调 `douyin_optional_status`，把风险声明读完
2. 决定继续 → 调 `douyin_optional_acknowledge`，`confirm: true`，`reason` 写一句你要做什么
3. 然后**自己**接自动化模块（本包不带）。建议顺序：

```
只读观察 → 确认不触发风控 → 单条写操作人工确认 → 低频 → 报错即停
```

## 为什么不做成"装了就自动干活"

因为那样等于把封号风险转嫁给不知情的人。
这个包的定位是：**让想做的人明确知道自己选了什么**，同时不提供危险能力。

## 支持的边界

- ✅ 帮你检查环境、提醒风险、记录确认
- ✅ 告诉你「只读优先、低频、失败即停」这些原则
- ❌ 不提供自动点赞/评论/私信/关注的代码
- ❌ 不提供绕过验证、伪造签名、多账号矩阵
- ❌ 不帮你在别人的账号或设备上操作
